## Blog の移行

管理者が 2027 年 3 月に定年退職するため、職場のマシンで運用していたブログを、GitHub Pages にアーカイブしました。既に旧ブログの各記事から、こちらにリダイレクトするようにしています。このリダイレクトを容易にするために、GitHub Pages 側の permalink は `YYYY-MM-DD.html` という形式にしています。そのため、slug を反映していません。

## 22 年半経った

仕事場のホームページを Blog 化したのが 2004 年 1 月 7 日なので、ほぼ 22 年半、運用していたことになります。ちなみに、[最初の記事]({{ site.baseurl }}{% post_url 2004-01-07-site-update %})では、

> 正月、去年の年末で自分のホームページを立ち上げて以来１０年が経過したことに気づいたので、久しぶりに自分のホームページをリニューアルすることにしました。ただ、単に書き換えるだけでは面白くないので、今流行の Blog スタイルにしてみました。

と書いていましたから、職場のマシンで Web サーバを動かし始めてから 32 年以上経ったことになります。

## tDiary から GitHub Pages (jekyll) への移行

旧ブログは [tDiary](https://tdiary.org/) で運用していましたが、記事を GitHub Pages の形式 ([jekyll](https://jekyllrb.com/))

tDiary 記法は空行の次は見出しになるなどレイアウトに文脈依存の部分があって (空行の次は見出しになるとか、でも行頭に空白が、

意図したレイアウトを実現するために結構 [ad hoc](https://e-words.jp/w/%E3%82%A2%E3%83%89%E3%83%9B%E3%83%83%E3%82%AF.html) な書き方をしていたので、jekyll 形式に置き換える際に文脈からレイアウトを推定する必要がありました。

## tDiary について

tDiary から GitHub Pages に移行していて思ったのは、tDiary が**めっちゃ高機能**だということでした。動的ブログシステムですが、軽量コンパクトなのに、単体でエディタやコメント機能、記事の管理機能などを持っており、プラグインで機能を拡張することができます。思いついたときに、スマホからでもブラウザから記事を更新したりできます。

だから、最初はそのままどこかの VPS（高専の後輩が創業者らしいところとか、卒業生が就職したところとか）に移すかと思っていたのですが、私が生物的に運用ができなくなったとき（）のことを考えて、GitHub Pages に置くことにしました。

## コメントの取り扱い

旧ブログは [tDiary](https://tdiary.org/) で運用していましたが、記事を GitHub Pages の形式 ([jekyll](https://jekyllrb.com/)) に書き換える際に、頂いていたコメントは削除しています。申し訳ありません。いくつかのコメントは記事内で引用したり、コメントで頂いた指摘を記事に反映したりします。コメント自体も移行することはできたのですが、

古い記事のアーカイブなので、もうコメントされることもなかろうと思います。もしかしたら、そのうち [giscus](https://github.com/giscus/giscus) か何かでコメント欄を復活するかもしれませんが（私の気力の方が……）
